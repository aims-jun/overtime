# AIMS 업무연장 UI 개편 설계

## 목표

직원은 모바일에서 월 누계를 바로 확인하고 10초 안에 추가 근무를 등록할 수 있어야 한다. 관리자는 직원별 업무연장 현황을 데스크톱과 모바일에서 가로 스크롤 없이 확인할 수 있어야 한다.

이번 개편은 토스의 제품 원칙에서 다음 특징을 참고한다.

- 가장 중요한 숫자와 행동을 먼저 보여준다.
- 정보 위계를 크기, 간격, 명도 차이로 명확하게 구분한다.
- 한 화면에 필요한 정보만 남기고 부가 기능은 문맥 안에 배치한다.
- 버튼과 아이콘의 크기, 선 굵기, 상태 표현을 일관되게 유지한다.

AIMS의 기존 라임 색상은 브랜드 포인트로 유지하되 넓은 면적에는 사용하지 않는다.

## 범위

### 포함

- 직원 업무연장 조회 화면
- 업무연장 등록 및 수정 바텀시트
- 직원 기록 목록과 삭제 확인 UI
- 관리자 조회 화면
- 관리자 모바일 기록 카드
- 실제 Excel `.xlsx` 다운로드
- 로딩, 빈 상태, 오류, 버튼 비활성 상태
- 반응형 레이아웃과 접근성

### 제외

- 인증 방식과 권한 정책 변경
- 업무연장 데이터 모델 변경
- 새로운 승인 또는 결재 기능
- 보고서 검색 조건 추가

## 디자인 시스템

### 색상

- 기본 글자: `#191F28`
- 보조 글자: `#6B7684`
- 약한 글자: `#8B95A1`
- 페이지 배경: `#F2F4F6`
- 카드 배경: `#FFFFFF`
- 구분선: `#E5E8EB`
- AIMS 포인트 라임: 기존 브랜드 색상을 유지하되 주요 행동과 선택 상태에만 사용
- 위험 행동: 붉은색 텍스트와 옅은 붉은 배경을 함께 사용

### 간격과 형태

- 기본 간격은 4px 배수로 구성한다.
- 모바일 좌우 여백은 20px, 데스크톱 콘텐츠 최대 너비는 현재 1120px를 유지한다.
- 카드 반경은 16~20px, 입력 필드는 12px, 버튼은 14px를 기준으로 한다.
- 모든 터치 대상은 최소 44px 높이와 충분한 간격을 확보한다.

### 버튼과 아이콘

- 주요 버튼, 보조 버튼, 텍스트 버튼, 위험 버튼 네 종류만 사용한다.
- 주요 버튼은 라임 배경과 짙은 글자를 사용한다.
- 아이콘은 동일한 SVG 아이콘 체계를 사용하고 기본 크기는 20px, 선 굵기는 2px로 통일한다.
- 아이콘 단독 버튼에는 접근 가능한 이름을 제공하고 44px 터치 영역을 보장한다.
- 추가, 닫기, 편집, 삭제, 달력, 펼침, 다운로드 아이콘을 문맥에 맞게 사용한다.
- 장식용 아이콘에는 스크린리더가 읽지 않도록 처리한다.

## 직원 화면

### 기본 화면

상단에는 간결한 AIMS 헤더와 사용자 메뉴를 둔다. 본문은 다음 순서로 구성한다.

1. 사용자 인사와 짧은 안내
2. 선택한 달의 총 추가 근무 카드
3. 조회 월과 최근 내역 제목
4. 날짜, 시간, 업무 내용, 근무 시간을 한 줄 규칙으로 정돈한 기록 목록
5. 모바일 하단의 고정된 `추가 근무 등록` 버튼

기존의 큰 영문 눈썹 제목과 40~64px 제목은 제거한다. 월 합계가 가장 먼저 보이되 페이지 전체를 압도하지 않도록 카드 안에 배치한다.

### 기록 목록

- 모바일에서는 날짜 블록, 업무 내용과 시간, 총 근무 시간을 3열로 정렬한다.
- 데스크톱에서도 같은 정보 순서를 유지해 화면 크기에 따라 의미가 바뀌지 않게 한다.
- 편집과 삭제는 각 행의 더보기 또는 명확한 아이콘 버튼으로 제공한다.
- 삭제는 브라우저 기본 확인창 대신 서비스 스타일의 확인 대화상자를 사용한다.
- 빈 상태에는 다음 행동인 `추가 근무 등록`을 함께 안내한다.

### 등록 및 수정

- 모바일에서는 바텀시트, 데스크톱에서는 중앙 대화상자로 표시한다.
- 배경 화면과 스크롤 위치는 유지한다.
- 날짜, 시작 시간, 종료 시간, 예상 추가 근무 시간, 업무 내용 순서로 구성한다.
- 시작·종료 시간은 기존과 동일하게 30분 단위 옵션을 사용한다.
- 저장 중에는 버튼을 비활성화하고 로딩 상태를 표시한다.
- 저장 성공 시 시트를 닫고 목록과 월 합계를 갱신한다.
- 오류는 입력 영역 안에서 즉시 확인할 수 있게 표시한다.
- Escape, 닫기 버튼, 취소로 닫을 수 있으며 포커스를 열었던 버튼으로 되돌린다.

## 관리자 화면

### 헤더와 필터

- 관리자라는 문맥과 `업무 연장 현황` 제목을 간결하게 표시한다.
- Excel 다운로드는 보조 버튼으로 우측에 배치하고 다운로드 아이콘을 함께 사용한다.
- 조회 월과 직원 필터는 한 카드 안에 정렬한다.
- 모바일에서는 필터를 한 열로 쌓되 입력 너비와 버튼 높이를 통일한다.

### 요약

- 전체 추가 근무, 등록 건수, 직원별 합계를 세 영역으로 표시한다.
- 전체 추가 근무 카드만 라임의 옅은 배경으로 강조한다.
- 모바일에서는 두 개의 숫자 카드를 먼저 보여주고 직원별 합계는 전체 너비를 사용한다.

### 기록 내역

- 데스크톱에서는 기존 표를 유지하되 열 정렬, 행 간격, 헤더 명도, 숫자 정렬을 정돈한다.
- 모바일에서는 표를 카드 목록으로 바꾼다. 근무일과 직원, 근무 시간, 업무 내용, 총 시간을 위계에 따라 배치한다.
- 동일한 데이터가 표와 카드 양쪽에서 중복 렌더링되지 않도록 반응형 표시 규칙을 명확히 둔다.
- 빈 상태와 오류 상태는 직원 화면과 같은 컴포넌트 규칙을 사용한다.

## Excel 다운로드

- 버튼 문구는 `Excel 다운로드`로 표시한다.
- 기존 CSV API와 프런트 URL 생성 코드는 실제 Excel `.xlsx` 다운로드로 교체한다.
- 보고서에 현재 조회 월과 선택한 직원 필터를 그대로 적용한다.
- 워크북에는 `업무연장 내역` 시트를 만든다.
- 열은 근무일, 직원 이름, 이메일, 시작 시간, 종료 시간, 추가 근무, 업무 내용 순서로 제공한다.
- 파일명은 조회 조건을 식별할 수 있는 `aims-overtime-YYYY-MM.xlsx` 형식을 기본으로 한다.
- 응답의 MIME type과 `Content-Disposition`을 Excel 파일에 맞게 설정한다.
- 생성 실패 시 기존 전역 오류 형식으로 처리하며 HTML 오류를 파일로 내려받지 않는다.

## 상태 및 접근성

- 최초 로딩은 레이아웃이 흔들리지 않는 스켈레톤으로 표시한다.
- 재조회 중에는 기존 데이터를 유지하고 필터 또는 관련 영역에 진행 상태를 표시한다.
- 오류에는 설명과 다시 시도 행동을 함께 제공한다.
- 포커스 표시를 명확히 유지하고 색상만으로 상태를 전달하지 않는다.
- 대화상자에는 올바른 역할과 제목 연결을 적용한다.
- `prefers-reduced-motion` 환경에서는 전환 애니메이션을 제거한다.

## 테스트 전략

- 직원 화면의 기본 위계, 바텀시트 열기와 닫기, 저장 후 갱신, 수정과 삭제 확인을 컴포넌트 테스트로 검증한다.
- 관리자 화면의 필터 동기화, 요약, 데스크톱 표와 모바일 카드에 필요한 의미 구조를 검증한다.
- Excel 엔드포인트의 필터 적용, 파일명, MIME type, 워크북 열과 행 데이터를 백엔드 테스트로 검증한다.
- 아이콘 단독 버튼의 접근 가능한 이름과 대화상자의 키보드 동작을 검증한다.
- 전체 웹 테스트, API 테스트, lint, production build를 완료 조건으로 삼는다.

## 구현 제약

- 기존 인증·권한·PostgreSQL 운영 데이터에는 손대지 않는다.
- API 데이터 계약은 Excel 다운로드를 제외하고 변경하지 않는다.
- 현재 운영 중인 SQLite 아카이브와 PostgreSQL 볼륨, 백업 설정은 변경하지 않는다.
- 사용자 소유의 `apps/coupang-ledger/` 디렉터리는 수정하거나 커밋하지 않는다.
