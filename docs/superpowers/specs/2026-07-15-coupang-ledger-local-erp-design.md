# 쿠팡 장부 로컬 ERP 설계

## 목표

현재 Google Sheets 장부의 수기 입력 흐름과 쿠팡 API 자동 수집 흐름을 하나의 로컬 웹 ERP로 통합한다. 사용자는 소싱, 상품 등록, 발주와 입고, 실제 매입금액, 물류비, 광고비와 사업비만 입력하고, 주문, 취소, 반품, 수수료와 정산은 가능한 범위에서 쿠팡 API로 수집한다. 대시보드는 두 원천을 SKU와 날짜 기준으로 결합해 예상 손익과 확정 손익을 보여준다.

## 운영 환경

- 당분간 한 대의 Mac에서 한 명이 사용한다.
- 프론트엔드는 현재 React 19와 Vite 앱을 유지한다.
- 백엔드는 현재 Node 서버를 장부 API 서버로 확장한다.
- 저장소는 로컬 SQLite 파일 하나를 사용한다.
- Google Sheets는 최초 데이터 이전에만 사용하고 이후 저장, 백업, 내보내기에는 사용하지 않는다.
- 향후 외부 배포 시 PostgreSQL로 이전할 수 있도록 SQL 호출을 저장소 모듈 안에 격리한다.

## 데이터 원천과 책임

### 직접 입력 원장

- 소싱 검토: 소싱 ID, 상품명, 공급처, 공급처 URL, 예상 판매가, 예상 매입원가, 판단과 메모
- 등록상품: 소싱 ID, 등록상품 ID, 옵션 ID, SKU ID, 쿠팡 상품명, 옵션명, 판매가, 상태
- 입고차수: 차수명, 발주일, 입고일, 국제물류비, 메모
- 입고상품: 입고차수, SKU 또는 임시 발주 품목, 수량, 실제 매입금액
- 운영비: 날짜, 유형, 금액, 부가세 처리, 메모
- 광고비: 날짜 또는 월, 금액, 배분 방식, 메모

### API 자동 원장

- 주문과 주문상품 원본
- 취소와 반품 원본
- 판매수수료와 관련 VAT
- 입출고, 배송, 보관, 반품 관련 비용
- 정산 주기와 실제 지급액
- 각 API 행은 쿠팡 식별자와 동기화 키로 중복 삽입을 막는다.

### 계산 결과

- 입고차수 물류비는 해당 차수의 총 입고수량으로 균등 배분한다.
- SKU 평균원가는 입고 수량과 입고 총원가의 가중평균으로 계산한다.
- 판매 상품원가는 판매수량 곱하기 해당 시점의 SKU 평균원가로 계산한다.
- 예상 손익은 주문 매출에서 원가, 예상 또는 API 수수료, 광고비와 배분 사업비를 차감한다.
- 확정 손익은 정산 API 값이 도착하면 실제 수수료, 취소, 반품과 지급액으로 대체한다.
- 미매핑 옵션 ID는 별도 처리함에 표시하고 손익 확정에서 제외한다.

## 주요 데이터 모델

- `sourcing_candidates`: 소싱 후보와 검토 결과
- `products`: 소싱 후보에서 등록된 쿠팡 상품
- `product_options`: 등록상품 ID, 옵션 ID, SKU ID와 옵션명 매핑
- `purchase_batches`: 발주와 입고 차수, 공동 물류비
- `purchase_items`: 차수별 품목, 수량, 매입금액과 배분원가
- `expenses`: 광고비, 택배비와 기타 사업비
- `api_sync_runs`: API 종류별 실행 범위, 상태와 오류
- `coupang_orders`: 주문 원본
- `coupang_order_items`: 옵션 ID 단위 주문상품 원본
- `coupang_adjustments`: 취소와 반품 원본
- `coupang_fees`: 판매수수료와 쿠팡 운영비 원본
- `coupang_settlements`: 정산과 지급액 원본

금액은 모두 원 단위 정수로 저장한다. 날짜와 시간은 원본 시각과 한국 날짜를 함께 보존한다. 소싱 단계에서 아직 SKU가 없는 품목은 소싱 ID와 발주 품목 ID로 기록하고, 상품 등록 후 옵션 ID와 SKU ID를 연결한다.

## 화면 구조

### 대시보드

- 조회기간, 마지막 API 동기화 시각과 동기화 버튼을 한 줄 도구 모음으로 제공한다.
- 매출, 상품원가, 쿠팡비용, 광고비, 사업비, 예상마진과 확정마진을 구분한다.
- 소싱 미완료, ID 미매핑, 원가 미등록, API 오류를 처리함으로 보여준다.
- 모든 요약값은 상세 원장으로 이동할 수 있다.

### 입력 화면

- `소싱검토`: 목록, 추가, 수정, 등록 전환
- `상품등록`: 소싱 품목에 쿠팡 등록상품 ID, 옵션 ID와 SKU ID 연결
- `입고매입`: 차수 생성 후 여러 SKU와 수량, 금액 입력, 공동 물류비 자동 배분
- `운영비`: 광고비, 택배비와 기타 사업비 입력

### 자동수집 화면

- `판매`: API 주문, 취소와 반품을 날짜와 SKU 기준으로 조회
- `정산`: 예상값과 API 확정값 비교
- `동기화 기록`: 조회기간, 신규 건수, 중복 건수, 미매핑 건수와 오류 확인

## UI 기준

- Tailwind CSS, shadcn/ui 컴포넌트 패턴, Lucide 아이콘을 사용한다.
- 수기 SVG 경로와 화면별 중복 CSS를 제거한다.
- 버튼은 명령의 중요도에 따라 기본, 보조, 위험, 아이콘 버튼으로 구분한다.
- 아이콘과 텍스트는 고정 높이 안에서 수평과 수직 중앙 정렬한다.
- 전체 폭 버튼은 저장 폼의 마지막 기본 동작에만 사용한다.
- 표는 고정 헤더, 수치 우측 정렬, 긴 텍스트 말줄임과 상세 보기, 빈 상태와 로딩 상태를 제공한다.
- 운영 도구답게 조밀하고 조용한 화면을 유지하며 장식용 카드와 큰 홍보형 문구는 사용하지 않는다.
- 데스크톱과 모바일에서 텍스트 겹침, 잘림, 불필요한 여백과 가로 스크롤을 검수한다.

## API와 저장 흐름

1. 사용자가 직접 입력 화면에서 저장한다.
2. Node API가 입력값을 검증한 뒤 SQLite 트랜잭션으로 기록한다.
3. 쿠팡 동기화는 기간별 API 원본을 중복 없이 저장하고 옵션 ID를 SKU에 연결한다.
4. 집계 API가 직접 입력 원장과 쿠팡 원장을 조회해 일별, 월별, SKU별 손익을 계산한다.
5. 프론트엔드는 집계 결과와 원장 상태만 표시하고 장부 계산식을 직접 소유하지 않는다.

## 오류 처리

- 입력 오류는 필드 가까이에 한국어로 표시하고 저장하지 않는다.
- API 오류는 기존 DB 값을 유지하고 동기화 기록에 실패 원인을 남긴다.
- 등록되지 않은 옵션 ID는 자동으로 임의 SKU를 만들지 않고 미매핑 처리함에 둔다.
- 동기화 버튼의 중복 실행을 막고 같은 API 행은 고유 동기화 키로 한 번만 저장한다.
- 계산에 필요한 원가가 없으면 마진을 0으로 단정하지 않고 `계산 보류`로 표시한다.

## 초기 데이터 이전

- 현재 Google Sheets 장부에서 소싱검토, 등록상품, 입고매입, 입고차수비용, 사업비와 광고비를 한 번 가져온다.
- 가져오기 전 미리보기에서 신규, 중복, 오류 행 수를 확인한다.
- 이전 완료 후 웹 DB를 유일한 원본으로 사용한다.
- 현재 코드에 들어 있는 예시 판매와 정산 행은 제거한다.

## 검증

- 저장소와 손익 계산은 자동 테스트로 검증한다.
- API 중복 수집, 옵션 ID 미매핑, 반품, 음수 정산과 원가 누락을 테스트한다.
- 각 입력 폼은 저장 성공, 유효성 실패와 서버 실패를 테스트한다.
- 최종 화면은 실제 로컬 서버에서 데스크톱과 모바일 크기로 확인한다.
- 주요 버튼의 클릭, 저장 후 재조회, 새로고침 후 데이터 유지와 API 동기화 상태를 직접 검증한다.
