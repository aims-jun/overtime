# 30분 단위 시간 입력 디자인

## 목표

업무 연장 기록의 시작 시간과 종료 시간을 30분 단위로만 입력하도록 제한한다. 모바일과 데스크톱 브라우저에서 동일한 선택지를 제공하고, 화면을 우회한 API 요청에도 같은 규칙을 적용한다.

## 사용자 인터페이스

- 기존 `time` 입력을 선택 목록으로 교체한다.
- 선택지는 하루 전체를 `00:00`부터 `23:30`까지 30분 간격으로 제공한다.
- 시작 시간과 종료 시간의 기본값은 현재와 동일하게 각각 `18:00`, `19:00`으로 유지한다.
- 수정 화면에서는 저장된 시간을 선택값으로 표시한다.
- 자정을 넘기는 기록과 “종료 시간은 다음 날입니다” 안내는 현재 동작을 유지한다.

## 프론트엔드 구조

시간 선택지 생성을 별도 순수 함수로 분리하고 시작·종료 선택 목록이 같은 결과를 재사용한다. `OvertimeForm`의 상태, 미리보기, 저장 요청 형식은 기존 `HH:mm` 문자열을 그대로 사용하므로 API 타입과 데이터 흐름은 변경하지 않는다.

화면에서는 목록에 없는 값을 새로 입력할 수 없다. 기존 데이터에 30분 단위가 아닌 시간이 있으면 수정 화면에서 해당 값을 선택지로 노출하지 않고 API 규칙에 따라 저장을 차단한다. 현재 서비스가 초기 개발 단계이고 운영 데이터 마이그레이션 대상이 없다는 전제다.

## 백엔드 검증

도메인 시간 계산에서 시작 시간과 종료 시간의 분 값이 `00` 또는 `30`인지 검증한다. DTO의 형식 검증도 같은 규칙으로 좁혀 잘못된 요청을 요청 경계에서 거부한다.

날짜 유효성, 자정 이후 계산, 16시간 최대 근무 시간, 중복 구간 검사는 기존 규칙을 유지한다.

## 오류 처리

화면에서는 허용된 선택지만 제공하므로 일반 사용자는 잘못된 분 값을 만들 수 없다. 직접 API를 호출해 `18:10`처럼 요청하면 기존 검증 오류 응답 형식을 사용한다.

## 테스트

- 웹 테스트에서 시작·종료 선택 목록이 30분 간격이고 `18:10` 같은 값이 없음을 확인한다.
- 기존 자정 이후 미리보기 테스트가 선택 목록에서도 유지되는지 확인한다.
- API 도메인 테스트에서 `00`, `30`분 입력은 허용하고 그 외 분 입력은 거부하는지 확인한다.
- 전체 테스트, 린트, 프로덕션 빌드를 실행한다.

## 제외 범위

- 근무 시간을 15분 또는 1시간 단위로 설정하는 관리자 기능
- 과거 비정상 시간 데이터의 자동 보정 또는 마이그레이션
- 날짜, 업무 내용, 업무 시간 계산 방식 변경
