# 로컬 복수 Origin 허용 설계

## 목적

Vite가 사용 가능한 포트를 자동 선택하더라도 로컬 프론트엔드가 Nest API의 Origin 검사를 통과할 수 있도록 `http://localhost:5173`, `http://localhost:5174`, `http://localhost:5175`를 명시적으로 허용한다.

## 설정 구조

기존 단일 값 `APP_ORIGIN`을 쉼표로 구분한 `APP_ORIGINS`로 교체한다.

```env
APP_ORIGINS=http://localhost:5173,http://localhost:5174,http://localhost:5175
```

환경 스키마는 값을 분리하고 공백을 제거한 다음, 하나 이상의 유효한 URL로 구성된 문자열 배열로 변환한다. 운영 환경에서는 배열의 모든 주소가 HTTPS여야 한다. 기존 `APP_ORIGIN`은 제거하며, `.env.example`, 로컬 개발 문서와 배포 문서도 새 이름으로 통일한다.

## 요청 처리

`OriginGuard`는 요청의 `Origin` 헤더가 `APP_ORIGINS` 배열에 정확히 포함될 때만 요청을 허용한다. 헤더가 없거나 목록에 없는 주소라면 기존과 동일하게 `INVALID_ORIGIN` 오류를 반환한다. 와일드카드, 포트 범위 추론, `127.0.0.1` 자동 허용은 추가하지 않는다.

프론트엔드는 현재처럼 `/api` 요청을 Vite 프록시로 전달한다. 브라우저가 보내는 원래 `Origin` 헤더를 백엔드가 검사하므로 프록시 구조는 변경하지 않는다.

## 테스트

- 환경 스키마가 쉼표로 구분된 Origin을 정규화된 배열로 변환하는지 검사한다.
- 운영 환경에서 하나라도 HTTP 주소가 포함되면 설정을 거부하는지 검사한다.
- `OriginGuard`가 목록의 각 허용 주소를 받아들이는지 검사한다.
- 목록 밖 주소와 Origin 헤더가 없는 요청을 거부하는지 검사한다.
- 기존 API 전체 테스트, 린트와 빌드를 실행해 회귀가 없는지 확인한다.

## 로컬 설정

실제 루트 `.env`도 세 개의 localhost 주소를 사용하도록 변경한다. 이 파일은 Git에 포함하지 않는다. Google OAuth 클라이언트의 승인된 JavaScript 원본에도 실제로 접속할 포트인 `5173`, `5174`, `5175`를 각각 등록해야 한다.
